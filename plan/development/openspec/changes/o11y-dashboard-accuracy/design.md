## Goals / Non-Goals

**Goals:**

- Make the tracked count inventory-marker based and expose age of the latest source marker.
- Calibrate state lookback/freshness from measured collection timing.
- Preserve current state and make expected-empty cases explicit without suppressing errors.
- Show the age and task provenance of the latest workflow result from its completion timestamp, with unknown provenance when the state is retained or completion time is unavailable.
- Include existing Overview signals with disjoint aggregate selectors and stable UIDs.
- Report a selected log source with no matching records as an explicit no-data observation, separate from query failure and service health.

**Non-Goals:**

- Change collector cadence, retention, service instrumentation, labels, production inventory, or Grafana version.
- Add a diagnostic profile, backend, dependency, or new production data path.
- Claim an Overview source is live until an exact query receipt proves it.

## Decisions

1. **Extend the existing verifier.** Add a validated list of exact selected panel titles whose empty result is an expected state. Report `expected_empty` separately from `pass`, `no_data`, and query error. Reject names outside the selected dashboard panels; never convert a query error or a required panel’s empty result into success. This reuses the existing read-only diagnostic and avoids a new Semaphore profile.
2. **Use collector inventory markers for estate coverage.** Count distinct `service` values from valid `step="none"` inventory marker records, including the `no_history` marker. Store the marker time as a numeric `marker_time_seconds` field in the existing record body; keep the Loki label set unchanged. For the 12 successive successful collector runs measured on 2026-10-10 (task duration 11.7–11.9 minutes, completion gaps 14.8–15.1 minutes, latest end 23:26:50 UTC), use a 45-minute latest-marker window and mark ages at 30 minutes stale. This is a calibration for that sample, not a lifetime guarantee. No separate Loki delivery-delay measurement was supplied; adjust using future run and verifier receipts. Missing or invalid marker evidence stays unavailable, never zero.
3. **Retain the collector as state authority.** The dashboard reads latest snapshots emitted by the collector, which merges last-known NetBox state under current results (`collect-service-conformance.yml:241-257`). Do not add a second state store or erase values when history is incomplete.
4. **Keep result provenance in the record body.** Conformance step records carry `task_id` and a numeric `completed_at_seconds` derived only from a valid timezone-aware task end time. A missing or invalid completion time is `unknown`; retained state has both task ID and completion time set to `unknown`. Dashboard age uses this completion time, never the later Loki event time. These fields stay in the body, not labels.
5. **Use separate, disjoint stream selectors.** Include the journal stream through its existing `signal="container"` label and preserve application container, access-log, span and conformance views. The legacy container selector excludes records marked as journal, access, span or conformance; each signal selector excludes conformance records. The container log view unions legacy container and journal records, so a record with both `container` and `signal="container"` appears only through the journal branch. Keep the all-stream view as a drill-down, never a source total. Confirm selectors against actual Dev receipts before accepting live coverage. When a selected source returns no records, expose that observation as no data for the source; do not turn it into a zero-rate or service-health assertion. Query errors remain failures.

6. **Expose unclassified records as missing classification.** The existing Overview source targets omit selected-service records without a nonempty `container` label and without a recognized `signal`. Add one bounded `unclassified` target to each of the source-rate and five-minute observation panels. Its selector requires the selected Logs service, excludes any nonempty `container`, excludes `container`, `access-log`, and `span` signals, and excludes conformance jobs. This is disjoint from legacy containers, journal containers, access, spans, and conformance. Label it unclassified; do not infer the record's owner, access meaning, ingestion cause, or service health. Leave producer templates outside this dashboard slice unchanged.

   **Live evidence (2026-10-17, read-only Grafana):** The `service-overview` UID had 12 panels and defaulted both service selectors to `agentgateway`. Its current five-source targets omitted records visible in the all-stream drill-down. For the exact `agentgateway` unclassified selector, Loki returned 90 lines over six hours and 482 over 24 hours; in the same six-hour query, spans returned 18, conformance 144, and access logs 0. These are point-in-time line counts, not health measures or a diagnosis. New dashboard acceptance remains pending deployment and read-back.
7. **Preserve identity and bounded cardinality.** Keep UIDs `service-conformance` and `service-overview`, datasource UIDs `prometheus` and `loki`, and the existing bounded label contract. Add no task ID or arbitrary values as labels.
8. **Reproduce bounded panel time overrides.** The dashboard verifier accepts `timeFrom` only when it is one positive Prometheus duration unit. Each panel uses that duration for range-query start, step sizing, and Grafana range built-ins; instant queries remain evaluated at the current end time. Other unsupported panel and target options remain refused.
9. **Keep table frames identifiable.** The per-service/step completion-age table applies the same labels-to-columns, frame merge, time-column exclusion, and value rename sequence as the latest step-status table, preserving service and step labels as row fields and labeling the age value explicitly.
9. **Make historical failure lines readable without changing source records.** In the existing seven-day “Recent failed task snapshots” panel, parse JSON fields at Loki query time and use `line_format` with Go `printf "%.180s"` rune precision to display service, step, task ID, and an error excerpt. After formatting, use Loki `keep job, service, step, status` so extracted JSON fields such as the full `error` do not remain in query-result labels while the original bounded labels stay available. The full original record remains stored and can be queried in Loki Explore. Configure exact Grafana dedup for visual display in this logs panel only: it compares adjacent returned lines, leaves interleaved repeats possible, and does not fetch replacements for lines hidden by dedup. Preserve `maxLines: 100`, the panel title, and dashboard UID. Do not change collector serialization, Loki ingestion, stored records, or current-state queries.

10. **Add bounded query observations separately from verifier validity.** Keep the existing pass/fail result based on query execution and finite result presence. For exact known provisioned query contracts only, add sanitized categorical observations for scrape health (`healthy`, `unhealthy`, `no_metrics`), inventory-marker freshness (`fresh`, `stale`, `no_data`, using the provisioned 1800-second boundary), current workflow failures (`present`, `none`, `no_data`), and completion age (`known`, `unknown`, `no_data`) when the exact table expression and `-1` mapping match. Match dashboard UID, panel title, target reference, datasource, mode, and the full source expression; a recognized title with any contract drift yields `unverified`. Never expose sample values, labels, expressions, log lines, provenance identifiers, or backend error text. Missing data is not healthy, a zero failure count is not a failed workflow, and a valid unhealthy scrape value remains valid query data. These observations do not assert expected-target completeness, selected Grafana UI identity/rendering, or service health from missing series; those require separate evidence.
11. **Identify current workflow failures without reading log bodies.** Extend only the exact selected `Latest step status by service` instant query. The controller parses the canonical workflow registry and passes its validated `steps` collection to the receiver-side verifier; no survey value can override it, and the receiver stays stdlib-only. Validate service and step labels against public component directories and that actual collection, require exactly those two labels, validate complete Loki sample shape and types before coercion, accept only the provisioned fail/pass/skip state codes, and return no more than 50 sorted failed pairs. Count invalid identities, extra labels, malformed samples, and duplicate series without echoing their contents; any such series makes the observation `unverified`. Every outcome reports `window_seconds: 2700` and `scope: latest_recorded_state`, including no-data outcomes when the dashboard's overall lookback is longer. The query's `last_over_time` reduction supplies one latest state per pair within 45 minutes: a newer pass or skip replaces an older failure. An empty result is `no_data`, not `none`; the result cannot establish whether failures exist outside the lookback or prove that a failure was cleared. Do not query the historical failure-log panel for this report because it includes record bodies. This remains a sanitized observation and does not change the dashboard query-data pass/fail outcome.

12. **Keep failed-pair uncertainty categorical and age joins explicit.** Split per-row unknown status series into fixed numeric label-shape, unregistered-identity, malformed-sample, and duplicate-pair counters. Preserve the total unknown count and keep the main observation `unverified` whenever it is nonzero; never echo unknown labels or values. Join completion ages only when the exact latest-status and exact completion-age panels are both explicitly selected. Do not add an implicit query. Validate the age panel's full existing expression and Loki datasource identity, plus exact service/step labels and complete finite samples. Attach a numeric age in seconds or null to each returned capped failure pair, with known and unknown age counts. The 2700-second lookback bounds which collector snapshot is observed; `completion_age_seconds` derives from that snapshot's workflow completion timestamp, not how long a failure has persisted. Missing, duplicate, malformed, negative, non-finite, boolean, or explicit `-1` unknown ages are null and age-unknown; if the age panel is unselected, set `completion_age_status` to `not_selected`, return null ages and count every returned pair unknown. Age reporting does not alter main observation status, query-data status, or imply application health.

## Risks / Trade-offs

- **[Risk] Collection timing or Loki delivery delay changes, making the current boundary too short or too permissive.** → The 30-minute stale and 45-minute unavailable boundaries are calibrated only to the supplied 12-run sample. Recheck collector and verifier receipts and adjust the values when later measured timing requires it.
- **[Risk] A panel is empty because its source is missing, but an exception hides it.** → Allow empty only for exact named panels whose absence is documented as healthy; keep required panel emptiness and every query error failing.
- **[Risk] Overview source selectors overlap or live logs are absent.** → Test selector disjointness and inspect exact Dev query results; report an empty result as a no-data observation, with the cause and ingestion status unverified rather than healthy or fixed.
